# Пуш-уведомления о начале эфира: что осталось сделать

Код готов и проверен целиком, кроме двух шагов в аккаунте Apple Developer —
их может сделать только владелец аккаунта.

## ⚠️ Сначала прочитайте это

В `ios/Runner/Runner.entitlements` добавлена строка `aps-environment`. Пока
шаг 1 ниже не сделан, **сборка на устройство и архив для App Store не будут
подписываться**: профиль не содержит права на пуши. На симулятор это не
влияет, там подпись не нужна.

То есть либо доводите настройку до конца, либо (если решите отложить) уберите
`aps-environment` из entitlements — тогда всё вернётся как было.

## Шаг 1. Включить Push Notifications у App ID

developer.apple.com → Certificates, Identifiers & Profiles → Identifiers →
`kg.irfan.irfan` → отметить **Push Notifications** → Save.

После этого профили нужно перевыпустить: в Xcode с автоматической подписью
достаточно снять и снова поставить галочку «Automatically manage signing»,
либо просто пересобрать.

## Шаг 2. Создать ключ APNs

Там же → Keys → «+» → имя любое → отметить **Apple Push Notifications
service (APNs)** → Continue → Register → **Download**.

Скачается файл `AuthKey_XXXXXXXXXX.p8`. Скачать его можно **только один раз**,
второй попытки Apple не даёт — сохраните надёжно.

Запомните три значения:
- **Key ID** — десять знаков из имени файла (`AuthKey_ABCD123456.p8`);
- **Team ID** — Membership details, тоже десять знаков;
- **Bundle ID** — `kg.irfan.irfan`.

## Шаг 3. Положить ключ на сервер

```bash
scp AuthKey_XXXXXXXXXX.p8 root@178.104.206.100:/etc/irfan/apns.p8
ssh root@178.104.206.100 'chmod 600 /etc/irfan/apns.p8'
```

И создать `/etc/irfan/apns.json`:

```json
{
  "key_path":  "/etc/irfan/apns.p8",
  "key_id":    "XXXXXXXXXX",
  "team_id":   "YYYYYYYYYY",
  "bundle_id": "kg.irfan.irfan",
  "production": false
}
```

`production` держите `false`, пока приложение ставится из Xcode напрямую:
сборки для разработки живут в песочнице APNs. После выхода в App Store
поменяйте на `true` — иначе Apple будет отвечать отказом на каждый токен.

Проверка после настройки:

```bash
ssh root@178.104.206.100 'python3 /opt/irfan-server/push.py "Проверка" "Тест"'
```

Скрипт напечатает, скольким устройствам ушло. Пока ключа нет, он честно
пишет «пуши не настроены» и ничего не делает — эфир от этого не страдает.

## Что уже сделано и проверено

**Приложение.** Отдельный переключатель «Уведомлять о начале эфира» в
настройках — намаз и эфир включаются независимо, потому что это разные по
смыслу вещи. При включении спрашивается разрешение, затем приложение
подписывается на APNs, получает токен и отдаёт его серверу вместе с ключом
устройства. Токен обновляется при каждом запуске: APNs выдаёт новый после
переустановки или восстановления из копии, и без обновления сервер слал бы
на мёртвый адрес.

Проверено на симуляторе целиком: токен в 160 знаков дошёл до сервера и лёг
в хранилище (запись 02.09.2026 13:00:41).

**Сервер.** `POST /push/register` — приём токена (мусор отклоняется с 400,
повторная регистрация того же телефона заменяет токен, а не плодит записи).
Хранилище `/opt/irfan-server/push-tokens.json` — права 600, лежит ВНЕ
раздаваемого каталога: внутри `api/` его скачал бы любой желающий.
`push.py` — отправка через APNs по HTTP/2 с подписью ES256; токены, на
которые Apple ответила 400 или 410, вычищаются сами.

`live-on.sh` шлёт уведомление **после** публикации статуса эфира: человек
нажмёт на уведомление сразу, и к этому моменту эфир уже должен отдаваться,
иначе он попадёт на «Сейчас эфира нет».

**Чего проверить нельзя без вас.** Настоящая доставка: токен из симулятора
Apple не принимает, а ключа для подписи пока нет. После шагов 1–3 проверьте
на живом телефоне — включите переключатель, начните эфир с другого телефона.

## Про подачу в App Store

Пуши меняют две вещи в анкете:

1. Появляется системный запрос разрешения на уведомления — он и так был
   ради азана, новых вопросов на ревью не будет.
2. Токен устройства — это идентификатор. В `PrivacyInfo.xcprivacy` уже
   объявлен `DeviceID` (связан с личностью, App Functionality), под него
   токен и подпадает. Отдельно ничего добавлять не нужно.

Отслеживания нет: токен уходит только на свой сервер и только чтобы
прислать уведомление об эфире.
