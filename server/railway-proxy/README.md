# Админка «Ирфан» по HTTPS через Railway

Зачем это нужно: панель отдаётся с голого IP по HTTP, и пароль администратора
идёт по сети открытым текстом. Railway даёт бесплатный адрес с сертификатом.

**Почему нельзя просто положить туда `admin.html`.** HTTPS-страница не имеет
права обращаться к HTTP-адресу — браузер блокирует такие запросы как
«смешанный контент». Панель на Railway, обращающаяся к `http://178.104.206.100`,
просто не загрузила бы ни одной строчки данных.

Поэтому здесь стоит прокси: браузер общается с Railway по HTTPS, Railway с
сервером «Ирфан» — по HTTP.

```
браузер ──HTTPS──> Railway ──HTTP──> 178.104.206.100:8090
   └── видео ────────────────HTTP───────────┘  (напрямую, минуя Railway)
```

## Развернуть

1. Создать проект на railway.app → Deploy from GitHub repo (или `railway up`
   из этой папки).
2. В Variables задать `ORIGIN` = `http://178.104.206.100:8090`.
3. Railway сам поднимет `python proxy.py` (см. Procfile) и выдаст адрес
   вида `https://irfan-admin.up.railway.app`.
4. Открывать `https://<адрес>/admin.html`.

## Что важно знать

**Участок Railway → Hetzner не зашифрован.** Он идёт по открытому интернету.
Это защищает от того, кто слушает вашу сеть (кафе, аэропорт), но не от того,
кто слушает магистраль. Полное решение — домен и сертификат на самом сервере
(`../enable-https.sh`), тогда прокси не нужен вовсе.

**Приложение студентов это не чинит.** Оно продолжает ходить на IP по HTTP,
и персональные данные учеников идут так же открыто. Прокси закрывает только
вход администратора.

**Видео через прокси не гоняется.** Запросы на `/uploads/` и `/hls/`
перенаправляются на сервер напрямую: иначе трафик шёл бы вдвое дальше и
упирался в лимиты Railway. Перемотка при этом сохраняется — проверено.
Загрузка новых файлов идёт насквозь через прокси (редирект браузер бы
заблокировал), поэтому большие уроки заливаются медленнее, чем напрямую.
