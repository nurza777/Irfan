# Выгрузка 140 ГБ уроков — как делать

## Коротко

1. Сжать на ноутбуке с RTX 3050 — **140 ГБ превращаются в ~20 ГБ**
2. Выгрузить сжатое по SSH (не через панель — она для отдельных файлов)
3. Разложить по курсам в админке

Сжимать до выгрузки, а не после: на сервере 4 ядра без видеокарты,
кодирование идёт втрое медленнее реального времени. RTX 3050 сделает то же
в десятки раз быстрее, и наверх поедет в семь раз меньше данных.

## 1. Сжатие на ноутбуке

Нужен ffmpeg:

    winget install Gyan.FFmpeg          # Windows
    sudo apt install ffmpeg             # Linux

Сначала прикинуть объём, ничего не трогая:

    python compress.py D:\Уроки D:\Готово --check

Потом сжать:

    python compress.py D:\Уроки D:\Готово

Инструмент сам найдёт NVENC на RTX 3050. Оригиналы не трогает — пишет в
отдельную папку. Если файл не поддался, кладёт его как есть, ничего не теряя.

### Про качество

Полностью без потерь сжать уже сжатое видео нельзя — файл станет больше.
Здесь «визуально без потерь»: разница неразличима, размер падает в разы.

Главный выигрыш даёт не кодек, а разрешение. Замерено на вашем же материале
(4K, 42 Мбит/с):

| Что делаем | Из 140 ГБ | Выгрузка |
|---|---|---|
| Сжать, оставив 4K | 91 ГБ | ~4 часа |
| **Сжать до 1080p** | **20 ГБ** | **~1 час** |

Уроки смотрят с телефона, где 4K от 1080p не отличить. Поэтому 1080p —
по умолчанию. Оставить исходное разрешение: `--keep-size`.

## 2. Выгрузка на сервер

Через `rsync` — он умеет продолжать с места обрыва, что на таком объёме
обязательно:

    rsync -avP --partial D:/Готово/ root@178.104.206.100:/opt/irfan-server/api/uploads/

Оборвалось — запустите ту же команду снова, докачает остаток.

Через админку заливайте единичные файлы: она удобна, но для сотни роликов
это лишние клики.

## 3. Разложить по курсам

Админка → **Курсы** → у нужного курса «+ урок» → выбрать файл из списка
загруженных → «Опубликовать студентам».

## Запасной вариант: сжатие на сервере

Если что-то залили без сжатия, сервер подберёт это сам — таймер раз в
15 минут, до трёх файлов за раз.

    systemctl list-timers irfan-compress     # когда следующий запуск
    systemctl start irfan-compress           # прямо сейчас
    tail -f /opt/irfan-server/logs/compress.log

Он осторожен: заменяет файл только если новый меньше и длительность
совпала, не запускается во время эфира и при нехватке места, работает с
низшим приоритетом, чтобы не мешать приложению.

Скорость на сервере — примерно 0.3× реального времени. Для отдельных файлов
нормально, для 140 ГБ — недели. Поэтому основной путь всё же первый.
